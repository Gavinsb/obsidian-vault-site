## Design Specificity Verdict

**Design-specific at the core, category-interchangeable at the frame.**

The mechanism PRODUCT.md calls the moat — "agent proposes, human approves each vault write" — is genuinely designed for, and it is the best work in the product: `AgentConsole.tsx` renders the validator honestly (blocking vs advisory, admin-gated override, audit link), `DocView.tsx` treats the approval gate as a state machine (saveBlocked, advisoryBlocking, draft-preserved-on-conflict, ETag-safe writes), and `KnowledgeMapView.tsx` explains every score and states "Scores never modify vault files."

But the shell that most routes live in is a generic dark vault-browser: sidebar + stat tiles + note lists + a stock search form + a force-directed blob + a rainbow tag cloud. `Dashboard.tsx` — the front door — shows eight neutral stat tiles and three near-duplicate activity lists and communicates nothing about the agent or the approval loop. A competitor could lift the Home/Search/Tags/Graph chrome unchanged; the one thing they could not copy is the least visible thing in the UI. The specificity is real but quarantined inside a note's Edit mode, admin-signed-in, and therefore under-surfaced.

**Deterministic scan:** `impeccable detect --json src/client` returned **0 findings, exit 0** (clean). Assessment B verified this is genuine, not suppression: re-run with `--no-config --no-inline-ignores` still empty; `.impeccable/config.json` holds only `{"buildPath":"code"}`; no `impeccable-disable*`/`impeccable-ignore` comments under `src/client`; URL-mode scan of the live app also clean. **No false positives** (nothing to judge). Notably the detector did **not** catch the tag-cloud `hsl()`/`rotate()` violation — those are inline JS styles in `TagsView.tsx`, outside the CSS/markup the detector scans — so a clean scan here does not mean the surface conforms to DESIGN.md.

## Overall Impression

A calm, disciplined tool whose strongest idea — the human approval gate over an agent-curated vault — is invisible from the front door. The Edit-mode approval machinery and the Knowledge Map explainer are exceptional and product-specific; the surrounding shell is competent but generic, and it spends the design system's scarcest resource (the accent) on a rainbow tag cloud. The single biggest opportunity: surface the approval loop where decisions begin.

## What's Working

1. **The approval-gate instrumentation is excellent and product-specific.** `DocView.tsx` + `AgentConsole.tsx` model the human-in-the-loop write as a legible state machine with honest scope copy and admin-gated override. Protect this.
2. **Knowledge Map explainability.** Formula weights, per-component contribution bars, normalization definitions, and "Scores never modify vault files" turn a ranking into something a skeptical owner can audit.
3. **Real design-system discipline.** `styles.css` has true token parity across dark/light, hairline structure, one button vocabulary, and correct a11y primitives in the newer code (`role="tablist"`/`aria-selected`, `role="status"` in `AgentConsole`).

## Priority Issues

**[P1] The product's differentiator is invisible outside one screen.**
- **What:** `Dashboard.tsx` and `SyncBar.tsx` present a generic vault dashboard; nothing signals an agent curates the vault or that a review queue exists.
- **Why it matters:** The agent/human approval loop is the stated moat (PRODUCT.md Positioning). A first-time or phone user sees a plain note app and the trust boundary is never surfaced where decisions start.
- **Fix:** Add an "Awaiting your review" surface — a dashboard stat tile plus a sync-bar segment ("2 changes pending approval") linking into the Changed/agent queue.
- **Suggested command:** `$impeccable shape` (agent-review surface)

**[P1] Destructive delete has no safety net surfaced, contradicting Product Principle #4.**
- **What:** The `DocView.tsx` confirm panel ("Delete this note permanently?") deletes permanently and `navigate("/")`s; no trash, no undo, no mention of the promised backup.
- **Why it matters:** "Never lose the human's knowledge" is a brand promise; the highest-anxiety moment is the least reassured, with no recovery path.
- **Fix:** On confirm, surface the backup outcome ("Backup written to …") or route deletion through a trash/`_trash` folder with restore.
- **Suggested command:** `$impeccable harden`

**[P2] The command palette is undiscoverable.**
- **What:** `⌘K` is bound in `App.tsx:87` but there is no visible trigger or hint; `SyncBar.tsx` offers only a plain search input.
- **Why it matters:** Recognition-over-recall; the fastest path is invisible and, on touch (the documented phone workflow), unreachable.
- **Fix:** Add a `⌘K`/"Commands" button to the sync bar and an equivalent entry in the mobile topbar.
- **Suggested command:** `$impeccable clarify`

**[P2] Global feedback is not announced, and errors leak raw strings.**
- **What:** `DocView.tsx:533` renders flash messages with no `aria-live`/`role`; `error && !doc` prints `String(e)`; no error boundary exists.
- **Why it matters:** Save/conflict/error feedback is invisible to screen-reader users, and raw exception text is user-facing on the failure path.
- **Fix:** Wrap flashes in `aria-live="polite"` (assertive for errors), add a React error boundary, map API errors to plain copy.
- **Suggested command:** `$impeccable harden`

**[P2] The tag cloud breaks the design system it lives in.**
- **What:** `TagsView.tsx:48` assigns `hsl(stableTagHue(t.tag) 70% 62%)` per tag and rotates chips (`rotate(-4deg|3deg)`); `styles.css` has zero `hsl()` elsewhere.
- **Why it matters:** It violates DESIGN.md's One Signal Rule, "don't invent additional accent hues," and the Pill-Is-A-Token rule — the loudest, least product-specific element on the site.
- **Fix:** Encode frequency with size only; render tags as `--accent-soft` chips or accent-outline pills.
- **Suggested command:** `$impeccable quieter`

**[P3] Navigation overload.**
- **What:** 14 flat top-level items in `App.tsx`, with Recent/Changed/Activity overlapping and Folders/Orphans weighted like Home.
- **Why it matters:** It is a >4-option decision point on every page; the IA makes the agent-review loop compete with edge-case views.
- **Fix:** Group into Browse (Home, Search, Recent, Folders) / Review (Changed, Health, Orphans) / Explore (Graph, Knowledge Map, Tags) / System (Settings).
- **Suggested command:** `$impeccable layout`

## Persona Red Flags

**The vault owner on a phone (the documented remote/phone workflow).** The approval loop is unreachable one-handed: nav hides behind `.menu-btn` "☰" with 14 items; no command-palette button (⌘K cannot be pressed on touch); the note edit path stacks `mode-toggle` + toolbar + `AgentConsolePanel` into one column; `.graph-svg` is a fixed 460px. Failing elements: `.mobile-topbar`, `CommandPalette` (no touch entry), `.mode-toggle`, `GraphView` `.graph-svg`.

**The skeptical trust auditor / first-time reader.** `Dashboard.tsx` shows `54 broken links`, `0 orphans`, `76 unrated` as neutral tiles with no severity or route to act; `HealthView.tsx` lists issues by raw `relPath` as link text, repeating the same long path with no title and no grouping action. Failing elements: `.stat` (no severity variant), `HealthView` `<Link>{i.relPath}</Link>`.

**The screen-reader / keyboard user.** Flash feedback in `DocView.tsx:533` has no `aria-live`; `HealthView` filter chips use `.chip` buttons with no `aria-pressed`; the palette overlay has no `role="dialog"`/`aria-modal`; the tag cloud's hue conveys nothing and its `title`-only affordance is thin. Failing elements: `.flash`, `HealthView` `.chip`, `.palette-overlay`.

## Minor Observations

- `Dashboard.tsx` Home-note heuristic (`folder === "00 Home"` ?? `/home|index/i`) can resolve to an arbitrary note, so "Open Home Note" may mislabel its target.
- Note count stated twice from different sources (sync bar `88 notes` vs dashboard `88 notes · 11 folders`).
- Time formatting inconsistent: relative `timeAgo()` on the dashboard vs absolute `toLocaleString()` in `ChangedView`.
- `Search.tsx` `run()` reads `ratingMin`/`tagFilter` from state while the mount-time deep-link path passes explicit filters — a stale-closure filter mismatch on `?tag=` arrivals.
- Emoji glyphs (`📖 ◇ ✳ 📁 ★ ☆`) sit beside lucide line icons; on emoji-less headless captures several render as tofu — flagging the inconsistency, not the capture artifact.
- `KnowledgeMapView` renders a bare `100` "score" with no stated scale.
- The "New note" `nav-item` is a `<button>` styled as navigation, placed in the sidebar footer below all 14 links.

## Questions to Consider

1. If the agent is the primary curator, why is the agent's work the least visible thing in the shell? Shouldn't Home open with what the agent changed and what needs approval?
2. DESIGN.md says the accent's scarcity is the point — so why does the tag cloud spend an entire rainbow on it?
3. The product has three competing "explore" surfaces (Graph, Knowledge Map, Tags). Which one is the signature interaction?
4. When the human approves a vault write, is there a moment of ceremony marking the trust boundary — or is it just a Save button?
5. The vault is the single source of truth, yet the UI never links to the actual Markdown unless you enter Edit → Raw. Shouldn't the source be one click from Read?
6. PRODUCT.md promises backups before destructive ops. Where in the interface does that promise become visible?

## Design Specificity Verdict

**Verdict: Specific — genuinely, not decoratively.** The sync bar is a live first-person statement of the product premise; the **approval gate** (`AgentConsolePanel` + `AgentInlineCard`, "Save blocked: blocking validator findings in the blocks you changed", the status-pill vocabulary `new/hrr/apply/rejected/finished/cancelled/halted`, "No model is executed by this site", the dashed `admin-instruction-block` with TARGET badge and ID pill) is a real domain object no interchangeable SaaS could show; the Knowledge Map (lens tabs + weight formula chips + per-component breakdown bars) is bespoke information design. The One Signal Rule and Hairline Rule hold in practice.

Where it drifts generic: the browse views (Recent/Folders/Favorites/Highly Rated/Tags) are conventional list pages — the familiar floor the specific surfaces stand on. **Caveat:** the agent-approval language is only visible once you open a note in edit mode *and* the note contains agent blocks; in the shipped vault there appear to be none, so the signature surface is effectively invisible at rest.

## Overall Impression

The app is visually disciplined and emotionally well-tuned at high-stakes moments, and its specificity is real. But this run's most important finding is a **P0 regression introduced by the earlier critique fixes**: the `--radius-sm`/`--radius-xs` tokens were undefined, so every button/input/nav row rendered square while cards stayed rounded — silently inverting the design system's core shape rule app-wide. A second self-inflicted regression (a dead "Unrated" deep link) also surfaced. Both were fixed during this pass.

## What's Working

1. **Recovery and error copy is best-in-class.** `friendlyError()` distinguishes 404/409/412/401/403-origin and never leaks an exception string; `bootErrorMessage()` translates fetch failures; the per-route ErrorBoundary keeps the shell alive and says the vault is untouched.
2. **The approval-gate visual language is specific and coherent.** Dashed agent blocks, mono IDs, pill statuses with one shared colour vocabulary, "blocks save" vs "advisory" tags, and `Save anyway (n)`.
3. **Disciplined visual system.** Accent budget respected, structure from hairlines + tonal steps, visible focus rings.

## Priority Issues

**[P0] Control radius tokens undefined — every button/input/nav row renders square (0px).** `--radius-sm` (56 uses) and `--radius-xs` (2 uses) were referenced but never defined; only `--radius: 10px`, `--radius-lg`, `--radius-pill` existed. Controls rendered 0px while cards were 10px and chips 999px — inverting DESIGN.md's "6px controls / soft-cornered rectangle" rule. `--radius-sm` was dropped when `--star-empty` was added; `--radius-xs` was never defined. **FIXED in this pass** (restored `--radius-xs: 4px`, `--radius-sm: 6px`). Follow-up: consider a token-existence guard so a 56-use token cannot vanish silently.

**[P1] Dashboard "Unrated" tile deep-linked to a dead end.** The tile was actionable but pointed at `/search?rating=unrated`, which `Search.tsx` ignores (it only reads `?q` and `?tag`) — a promised drill-through that silently no-oped. **FIXED in this pass** (now `/health?kind=unrated`, and Broken links → `/health?kind=broken-link`; HealthView seeds its filter from `?kind`).

**[P1] Health page is an undifferentiated wall with a count/row mismatch.** `All (127)` renders 73 file-grouped rows; the broken-link case is fixed (one expandable row per file — good), but the page still opens on 73 rows dominated by "No rating set.", with no severity ordering, progress framing, or explanation of whether 1,272 issues is expected for an 88-note vault. The chip math (54+73=127) vs 73 rows will read as a bug. **Fix:** label chips by *issue* count and the list header by *file* count ("73 files · 127 issues"); sort groups by severity then count; add one orientation line.

**[P2] Header sync bar is dense and wraps awkwardly on mobile.** At 390px the sync bar (dot + label + search + "Commands ⌘K" + user) wraps to two lines; the `⌘K` hint is meaningless on touch and the user button adds a fifth target. **Fix:** collapse search to an icon that opens the palette, hide `⌘K` glyph, move the user control into the drawer.

**[P2] Knowledge Map control density exceeds the 4-option threshold.** 5 lens tabs + 4 filter controls + per-row "Explain score" + definitions disclosure + formula chips — ~7 decision points above the fold; loading is a text line, not a skeleton. **Fix:** collapse folder/tag/rating into one "Filters" disclosure; show top 5 immediately; render a skeleton.

**[P3] Dead CSS / hardcoded colours drift from tokens.** `.tag-cloud`/`.tag-cloud-item` rules survive though the component uses `.tag-visual-cloud`; `GraphView.tsx` hardcodes `#37c877`/`#4f8cff`/`#e0a63a`/`rgba(0,0,0,.25)` instead of `--ok/--accent/--warn`, so graph colours don't follow the theme.

**[P3] `index.html` hardcodes `data-theme="dark"` while App defaults to `system`** — a light-preferring user can see a dark first paint that flips to light. **Fix:** set the initial theme from `prefers-color-scheme` in a tiny inline script.

## Persona Red Flags

**Phone at 23:40, checking what the agent did today.** The Health page opens on 73 rows of "No rating set." with no "here's what matters" framing — a chore list, not reassurance; the sync bar wraps and offers a `⌘K` hint that does nothing on touch.

**Mid-review, approving an agent proposal.** The status dropdown is a bare `<select>` with 7 options, some disabled by invisible rules ("A halt needs a reason…" only on hover) — on mobile `title` tooltips don't exist, so the rule is unreachable; a blocked save states the reason but offers no jump to the findings below the fold.

**First run, exploring the app's most impressive feature.** The Knowledge Map greets them with 5 tabs + 4 filters + a disclosure, with the ranked list below the control block; agent blocks are invisible in the default read view (`Show agent blocks` is admin-only inside the ⋯ menu).

## Minor Observations

- Chips use `--radius-pill` while sibling controls were `0px` — the contrast made the missing tokens conspicuous (now fixed).
- `stat-go` arrows are accent-coloured on every actionable tile — identical to link chevrons, slightly blurring "tile" vs "link".
- Health group rows have two click targets (file link + expand button) without clear affordance separation.
- The tag visual cloud is large (`min-height: 360px`) and pushes the directory below the fold on mobile.
- No confirmed `:focus-visible` styling for `.stat-link` or the health group link (only buttons/stars define it).
- `Search` "Try:" chips disappear after the first search with no way back.
- Toolbar `← Back` uses history; deep-linked users may land with a Back that exits the app.

## Questions to Consider

1. If the agent-approval gate is the product's soul, why is it the hardest thing to find? Should the read view surface pending proposals as a first-class banner instead of burying `Show agent blocks` in an admin-only overflow menu?
2. What does "healthy" mean for an 88-note vault with 1,272 issues? Without a target or trend, is the Health page a report or a to-do list?
3. Why does the dashboard's most prominent number ("0 changed today") describe the app, not the vault?
4. Should an undefined 56-use token be treated as a design-system *test* failure — is a token-existence guardrail warranted?
5. Is the Knowledge Map a lens or a destination? Would one "what deserves attention" answer, with lenses secondary, carry more weight?

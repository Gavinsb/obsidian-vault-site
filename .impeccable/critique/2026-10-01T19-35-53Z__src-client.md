## Design Specificity Verdict

**7.5/10 — mostly product-grounded, with two category-interchangeable zones.**

The core is unmistakably this product: the **Knowledge Map** (lens tablist, weighted formula chips, "Explain score" with normalized component bars, and "Scores never modify vault files") is a genuine agent-corpus instrument; the **agent-block language** (blueprint cards, paired brackets, status pills, `halted` in salmon, `finished` visibly sweep-only) is specific and consistent across read view, console, and help; and **read-only-by-construction honesty** ("Nothing here modifies the vault", "No model is executed by this site") writes the product promise into the chrome.

Where it drifts generic: **Dashboard** could be any note tool (stat grid + activity feed), and its activity/timeline pair is empty while the tiles say "20 changed today" — the single biggest specificity miss. **Tags** and **Folders** are commodity. **Sidebar groups** are a real improvement but still a flat 15-row list — an IA patch, not a product-specific navigational idea.

## Overall Impression

A handsome, disciplined instrument whose best idea is still under-surfaced. The design system and the safety design are excellent, and today's fixes landed (26 → 30). The remaining problems are not visual — they are informational: the Dashboard's numbers are dead ends, the Health "review" surface is a 127-row dump, and the surface that exists to prove the agent is working ("What's changed?") contradicts the Dashboard and renders empty. The biggest opportunity: make the home screen a *desk* (what the agent is waiting on) instead of a *library*.

## What's Working

1. **A disciplined, genuinely handsome design system.** One accent at ≤10% coverage, structure from hairlines and three tonal steps, shadows only for floating layers, weight-not-size hierarchy; the light theme mirrors token-for-token without a hardcoded leak.
2. **Safety is designed, not bolted on.** Delete names the backup; the conflict flow preserves the draft and says so; the Save gate explains why it is disabled; the ErrorBoundary states "Your vault files were not changed."
3. **The Knowledge Map is a real product idea, well executed.** Lens tabs, weighted formula chips, per-score breakdown, and a hard "scores never modify vault files" boundary give the human a way to audit the agent's sense of importance.

## Priority Issues

**[P0] "What's changed?" contradicts the Dashboard and renders empty.**
- **What:** `GET /api/changes` returns all-empty buckets so `/changed` says "No changes recorded yet", while `GET /api/activity` returns `pagesChangedToday: 20, pagesChangedThisWeek: 86` with `lastChanges: []`. The Dashboard renders those counters beside an empty activity list, and one click away ChangedView denies any change happened.
- **Why:** This is the surface whose whole job is to prove the agent's work; a contradiction converts "agent proposes, human approves" from a promise into a suspicion.
- **Fix:** Make `/changed` and the Dashboard activity card read from one source; if the journal isn't populated, say so honestly; reconcile the counters with the buckets.
- **Suggested command:** `$impeccable clarify` (server journal + endpoint alignment)

**[P0] Health view is a 127-row undifferentiated dump.**
- **What:** 54 broken links in one file render as 54 identical rows with the same path; 73 unrated notes as 73 more; sorted by `kind` only — no grouping, rollup, dedupe, or "fix in editor".
- **Why:** It is the app's only remediation entry point and it maximizes cognitive load exactly when the user is trying to act — and the amber "54 Broken links" tile routes straight into it.
- **Fix:** Group by file with counts and an "Open in editor" link; collapse repeats; show kind counts first and let the user drill; surface broken links in the note's context rail.
- **Suggested command:** `$impeccable layout` (HealthView grouping)

**[P1] The Dashboard's headline numbers are dead ends.**
- **What:** Total notes / Links / Backlinks / Tags / Avg rating are inert; "Unrated 73" links to `/rated` = *Highly Rated*, which filters `rating !== undefined` and sorts descending — the opposite of the labelled destination.
- **Why:** A number the user cannot act on teaches them the UI lies; the Unrated→Highly Rated mismatch is a concrete recognition failure.
- **Fix:** Route "Unrated" to `/health?kind=unrated` (or a dedicated view); add a subtle "→" affordance to every actionable tile.
- **Suggested command:** `$impeccable polish` (Dashboard tiles)

**[P2] Two stacked control bars above every note, plus a mode switch that discards silently.**
- **What:** App-level sync bar sits directly above the sticky doc toolbar; on mobile this consumes ~250px before content. Switching Read→Edit→Read drops a draft with no warning, while Cancel does warn.
- **Why:** Every note visit pays a chrome tax, and the one destructive-ish note interaction is the one without a guard — undercutting the "Scroll-Once Rule".
- **Fix:** Collapse the toolbar's secondary actions into ⋯ at narrow widths; hide/condense the sync bar inside a note; guard the mode switch with the existing `confirmCancel` panel when dirty.
- **Suggested command:** `$impeccable polish` (DocView toolbar)

**[P2] The agent approval gate has no queue, only a per-note console.**
- **What:** Agent blocks are exposed only inside a note's Edit mode — no "pending reviews" surface, no count in the Review group, no sync-bar badge; the console row is ~15 controls with no progressive disclosure.
- **Why:** The human cannot see the agent's outstanding work without already knowing which note to open; the defining loop is invisible at the top level.
- **Fix:** Add a "Pending agent reviews" count to the Review nav group and a Dashboard card; split the console row (status + Accept/Reject first, body/pairing/halt surgery behind a disclosure).
- **Suggested command:** `$impeccable polish` (AgentConsole progressive disclosure)

**[P3] Residual consistency and polish debt.**
- **What:** `Extras.tsx` uses literal emoji against lucide elsewhere; boot error prints raw `{error}`; ErrorBoundary wraps `<App/>` but not each route; legacy `word-cloud`/`tag-cloud` CSS remains; `Search` fires `run(tag, {tag})` for a tag-only deep link.
- **Why:** Small, but they accumulate into "unfinished".
- **Fix:** Lucide icons; friendly boot-error mapper; per-route boundary; delete dead CSS; fix the tag deep-link query.
- **Suggested command:** `$impeccable polish` (cleanup)

## Persona Red Flags

**Persona A — Gav on his phone via the Cloudflare tunnel (the stated primary context).** On `/note/...` at 390px the mobile topbar + sync bar + doc toolbar stack to ~250px of chrome before content; the doc toolbar's ⋯ menu and mode toggle sit adjacent with no visible danger cue; the Dashboard's 8 tiles wrap to 4 rows, pushing "Recently modified" far below the fold — the most common mobile intent is the least reachable thing.

**Persona B — a second admin doing a vault health pass.** Clicks "Broken links 54" → 127 flat rows, 54 the same file; opens the offending note to fix it and the read view looks clean (context rail shows Backlinks only); opens Edit and the Save gate's reason is console jargon requiring Editing Help to decode.

**Persona C — an evaluator deciding whether to trust the agent.** Dashboard says 20 changed today; "What's changed?" says none were ever recorded — trust gone in two clicks; the sidebar shows no counts or pending indicators, so nothing reveals an approval queue exists; `hrr`/`TARGET:`/`apply` appear with no inline explanation.

## Minor Observations

- **"Commands ⌘K" uses the macOS glyph** on a Linux-hosted app — show `Ctrl K` when not Mac.
- **Two overlapping search entry points:** sync-bar "Search vault…" and the palette's "Search vault" command; neither is canonical.
- **The note read view shows no outgoing-links list** (only `Backlinks (n)`), so the user cannot see what a note points at — or the broken links it owns.
- **`New note`** creates a frontmatter stub silently with no preview or folder picker.
- **`HealthView` has no loading state** — `issues` starts `[]`, so it can briefly assert "Looking healthy" before data arrives.
- **`RatingStars` renders a visible "unrated" label** in list contexts where it repeats dozens of times.
- **The tag cloud's frequency encoding is now size + weight only**, but `clamp(0.9rem, …2.8rem)` compresses mid-frequency tags; with 163 tags top and middle are hard to distinguish.
- **Legacy `.word-cloud*` CSS** survives though the component now uses `.tag-visual-cloud`.
- **`/note` (no path) redirects to `/`**, but Back uses `navigate(-1)`, which can walk the user out of the app if the note was opened externally.

## Questions to Consider

1. If the thesis is "agent proposes, human approves," why does the home screen show a library (recently modified) instead of a desk (what the agent is waiting on you to approve)?
2. The Dashboard and "What's changed?" disagree about whether anything changed today. Which is the source of truth — and why is the user the one who has to figure that out?
3. The Health page lists 127 issues but offers no way to resolve any of them. Is this a health panel or a guilt panel?
4. "Unrated" links to "Highly Rated." If a tile's label and its destination can disagree, what else in this UI is quietly lying?
5. The agent-block vocabulary is precise and internally consistent — but it's a private language. Should the agent's dialect be translated into the human's?
6. The design system says "exactly one region scrolls" — yet on a note view you scroll past two stacked control bars. Which rule wins when they conflict?
7. The tag cloud lost hue and rotation for the One Signal Rule. Did it lose its only scanning affordance, and is size-only still readable at 163 tags?
